## Executive Summary

In `XhcInitializeEndpointContext`, two `EndpointTransferRing` allocations have NO NULL CHECK AT ALL (not even ASSERT) before the result is stored and passed to `CreateTransferRing` which dereferences it. Line 2995 (BULK endpoint case) and line 3046 (INTERRUPT endpoint case) follow the identical pattern. Additionally, line 3002 dereferences `EndpointTransferRing->RingSeg0` in a DEBUG print.

This advisory is one of a set reported to VulnCheck on 2026-06-25 for coordinated disclosure to the EDK II maintainers. After several follow-ups over the following months no response was received. 126 days after the initial report, ByteRay is publishing the findings in good faith so that affected integrators can assess and remediate them. All findings were identified against EDK II commit `70741a15d9a714323a5598eac47727e60507e22f` (master, 2026-06-21).

## Affected Products and Versions

- Vendor: TianoCore
- Product: EDK II (`MdeModulePkg`)
- Affected commit: `70741a15d9a714323a5598eac47727e60507e22f` (master, 2026-06-21). The code is present on that commit and later revisions that have not changed it.
- **Location:** `MdeModulePkg/Bus/Pci/XhciDxe/XhciSched.c:2995`
- **Function:** `XhcInitializeEndpointContext`
- **Category:** `error_handling`

## Technical Details

**Controllability:** `SEMI_TRUSTED` — confidence: **high**. Called from `XhcSetConfigCmd` when configuring a connected USB device's endpoints.

**Data Flow**

At line 2995 (BULK endpoint case), `EndpointTransferRing = AllocateZeroPool(sizeof(TRANSFER_RING))` has NO CHECK AT ALL. At line 2997, `CreateTransferRing` dereferences NULL. At line 3002, `EndpointTransferRing->RingSeg0` dereferences NULL in a DEBUG print. Line 3046 (INTERRUPT case) follows the identical pattern.

**Affected Callers**

- `XhcSetConfigCmd`
- `XhcSetInterface`

**Sanitization / Security Controls**

- None.

## Reachability and Preconditions

Attacker position and trust level for this issue are stated in the Controllability line and Data Flow above, and the concrete trigger is in Reproduction below.

**Exploitability:** **Low**  
**Realism:** **Low**

## Reproduction

1. Physical access to USB port; memory pressure during USB device configuration.
2. `XhcSetConfigCmd` calls `XhcInitializeEndpointContext` to configure endpoints.
3. At line 2995 (BULK endpoint), `AllocateZeroPool` for `EndpointTransferRing` returns NULL with NO CHECK.
4. At line 2997, `CreateTransferRing` dereferences NULL.
5. Line 3046 (INTERRUPT case) follows the identical pattern.

## Impact

Denial of service — firmware crash during USB configuration.

## Remediation and Mitigation

As of commit `70741a15d9a714323a5598eac47727e60507e22f` this issue is unfixed upstream and no CVE has been assigned. Check the allocation result for NULL before dereferencing it and fail the operation cleanly when allocation fails. The specific control that is absent or ineffective is identified in the Sanitization / Security Controls list under Technical Details.
